# Agent / Sub-Agentワークフローと終了条件

## 基本フロー

1. Humanが目的、制約、公開範囲、受入条件を定義する
2. Orchestratorが作業を調査・実装・レビュー・テストの単位へ分解する
3. 各Agentが担当範囲の結果、根拠、不確実性、未完了事項を出力する
4. Approval Gateで、人間が継続・修正・停止・公開可否を判断する
5. 承認された変更のみをGitの変更履歴へ残し、CI・テストで検証する
6. Humanが最終判断を行う

## 役割分担の原則

- 一案件または一目的ごとに作業コンテキストを分ける
- 調査結果と実装判断を混同しない
- Review / Testは、実装Agentと異なる観点で確認する
- AIの結果には根拠・前提・不確実性・未確認事項を添える
- 目的や要件が変わる場合は、Humanへ戻して再承認する

## 終了条件

目標達成だけを終了条件にせず、次のいずれかで安全に停止または人間判断へ戻します。

| 条件 | 取るべき扱い |
| --- | --- |
| 1. 目標達成 | 受入条件と検証結果を確認し、Humanが完了判断を行う |
| 2. 最大ターン・試行回数到達 | 無限試行を避け、現状・失敗理由・次の判断をHumanへ渡す |
| 3. 予算上限 | コスト消費を止め、継続可否をHumanが判断する |
| 4. 人間による停止 | 直ちに作業を停止し、未実行操作を明確にする |
| 5. エラー | 自動復旧を前提にせず、原因・影響範囲・再試行可否を整理する |
| 6. 必要データ不足 | 推測で補わず、必要なデータと不足の影響を提示する |
| 7. 期限到達 | 未完了内容と品質状態を明示してHumanへ戻す |
| 8. 品質基準未達 | 公開・確定・次工程への移行を止め、修正または中止を判断する |

## Sub-Agentの扱い

Sub-Agentは、限定された調査や検証を並行化するために使用します。ただし、Sub-Agentの出力は最終結論ではありません。OrchestratorまたはHumanが、根拠・矛盾・未確認事項を統合して判断します。
