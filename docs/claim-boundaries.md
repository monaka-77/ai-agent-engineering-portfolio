# 公開上の主張境界

採用ポートフォリオでは、魅力的に見せることと、事実を正確に伝えることを両立させます。この資料では、実装済みの事実、個人開発環境での設計・検証、将来構想を混同しません。

## 表現の区分

| 区分 | このポートフォリオで使う表現 |
| --- | --- |
| 公開実装の事実 | 「ProjectControl Portfolioで公開している」「Python・テスト・CIで確認している」 |
| 設計・検証 | 「個人開発環境で設計・検証している」「ワークフローへ組み込んでいる」 |
| 将来構想 | 「今後のフェーズで検討している」「公開予定」 |

## 使用しない表現

- 本番運用中
- 商用運用中
- 顧客環境で稼働中
- 企業導入済み
- 実績○社
- 実装していないRAG、MCP、LLM API、クラウド運用の経験を示す表現

## Public / Privateの境界

公開資料には、一般化した設計思想と公開可能な実装証拠のみを載せます。Privateプロジェクトのソースコード、URL、インフラ詳細、API情報、認証情報、クライアント情報、実データ、内部設計は転載しません。

非公開に保つことは、成果を隠すためではなく、秘密情報・実データ・本番環境を不用意に公開しないための運用判断です。
