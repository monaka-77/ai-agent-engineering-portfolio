# 評価と受入基準

## 評価の考え方

AIエージェントの品質は、もっともらしい出力だけでは評価しません。目的への適合、根拠、変更の安全性、検証可能性、停止判断を確認します。

この文書は評価の**設計基準**であり、特定のモデル、RAG、MCP、LLM APIの性能ベンチマーク結果を主張するものではありません。

## 評価観点

| 観点 | 確認内容 |
| --- | --- |
| 目的適合 | 承認済みの目的・制約・受入条件に対応しているか |
| 根拠 | 調査結果に出典、前提、不確実性が含まれるか |
| 最小権限 | Agentに不要な情報・権限・外部操作を与えていないか |
| 変更品質 | 差分、影響範囲、テスト方法、ロールバック可能性が示されるか |
| 再現性 | Git履歴、テスト、CIにより検証を再実行できるか |
| 停止の適切さ | エラー・データ不足・品質未達時に推測で進めていないか |

## 受入基準の例

変更を次工程へ進める前に、少なくとも以下を確認します。

1. 目的と対象範囲が明確である
2. Private情報や認証情報を含まない
3. 変更差分と影響範囲を説明できる
4. 必要なテストまたは確認手順が実行済みである
5. 未確認事項・制約・リスクが明示されている
6. 人間の承認が必要な操作を自動で確定していない
